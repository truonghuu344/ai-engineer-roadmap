Code ML không chỉ chạy trong notebook. Bạn cần điều khiển máy chủ GPU (terminal), lưu lịch sử thay đổi (Git), chia sẻ và nhận góp ý (GitHub), và train trên GPU miễn phí (Colab). Nhà tuyển dụng nhìn GitHub của bạn trước khi đọc CV, nên bài này cũng là bước đầu xây hồ sơ.

Terminal Linux đủ dùng

Vì sao cần học

Máy GPU thuê trên cloud (RunPod, Lambda, máy chủ trường) không có giao diện đồ họa: bạn chỉ có một cửa sổ terminal qua SSH. Biết khoảng 20 lệnh là đủ để cài môi trường, chạy train, theo dõi log và dọn ổ đĩa mà không phải tải file về máy.

Cấu trúc thư mục và đường dẫn

Linux có một cây thư mục duy nhất bắt đầu từ /. Thư mục nhà của bạn là ~ (ví dụ /home/truong). Đường dẫn tuyệt đối bắt đầu bằng /; đường dẫn tương đối tính từ thư mục hiện tại, với . là "ở đây" và .. là "thư mục cha".

pwd                      # đang ở đâu: /home/truong/project
ls -lh                   # liệt kê, -l chi tiết, -h dung lượng dễ đọc (12K, 3.4G)
cd data/raw              # vào thư mục con (tương đối)
cd ..                    # lên một cấp
cd ~                     # về thư mục nhà
mkdir -p runs/exp1       # tạo thư mục, -p tạo luôn thư mục cha nếu chưa có
cp a.py b.py; mv b.py src/; rm old.log   # chép, di chuyển/đổi tên, xóa
rm -r tmp/               # xóa cả thư mục (không có thùng rác, cẩn thận)

Đọc và tìm trong file

cat config.yaml          # in cả file
head -n 20 train.csv     # 20 dòng đầu: xem nhanh cấu trúc CSV
tail -n 50 train.log     # 50 dòng cuối
tail -f train.log        # theo dõi log đang được ghi (Ctrl+C để thoát)
grep "val_acc" train.log # chỉ in dòng có chuỗi "val_acc"
grep -c ERROR train.log  # đếm số dòng khớp
grep -v ERROR train.log  # in các dòng KHÔNG khớp
wc -l train.csv          # đếm số dòng (số mẫu + 1 dòng tiêu đề)

Pipe: ghép lệnh nhỏ thành công cụ lớn

Dấu | đưa đầu ra của lệnh trước làm đầu vào của lệnh sau. Mỗi lệnh làm một việc nhỏ; ghép lại giải được bài khó.

Ví dụ từng bước

Một file val.log có 8 dòng:

step 100 val_acc 0.61
step 200 val_acc 0.68
WARNING slow dataloader
step 300 val_acc 0.72
ERROR disk full
step 400 val_acc 0.74
ERROR retry failed
done
  • grep -c val_acc val.log → 4
  • cat val.log | grep -v step | wc -l → 4 (8 dòng trừ 4 dòng có "step")
  • grep val_acc val.log | tail -n 1 → step 400 val_acc 0.74 (kết quả mới nhất)
  • grep -E "ERROR|WARNING" val.log | wc -l → 3 (-E cho phép "hoặc" bằng dấu |)

Thêm vài lệnh nối pipe hay dùng: sort (sắp xếp), sort -n (theo số), uniq -c (đếm dòng trùng liên tiếp), cut -d, -f2 (lấy cột 2 của CSV). Ví dụ đếm số mẫu mỗi nhãn: cut -d, -f2 train.csv | sort | uniq -c.

python train.py > train.log 2>&1     # gộp cả lỗi (stderr, kênh 2) vào cùng file

Git hoạt động thế nào

Vì sao cần học

Không có Git, bạn sẽ có train_final.py, train_final2.py, train_final_THAT_SU.py và không nhớ cái nào cho accuracy 82%. Git lưu mọi phiên bản, cho biết ai đổi gì khi nào, cho phép quay lại phiên bản cũ, và là cách duy nhất để làm việc nhóm trên cùng một codebase.

Commit là một bức ảnh chụp

Mỗi commit là ảnh chụp toàn bộ dự án tại một thời điểm, kèm lời nhắn, tác giả, thời gian, và một mã định danh (hash) như a3f9c21. Lịch sử dự án là chuỗi các commit nối nhau.

Ba khu vực (và một khu vực từ xa)

Khu vực Ý nghĩa Lệnh đưa vào
Working directory file bạn đang sửa (sửa file)
Staging area những thay đổi sẽ vào commit tiếp theo git add <file>
Repository lịch sử các commit, nằm trong thư mục .git git commit -m "..."
Remote bản sao trên GitHub git push

Vùng staging tồn tại để bạn chọn những gì vào commit. Bạn sửa 5 file nhưng chỉ 2 file liên quan đến việc "thêm checkpoint" thì chỉ add 2 file đó, commit, rồi xử lý 3 file kia ở commit khác. Lịch sử sẽ dễ đọc và dễ quay lui.

Vòng làm việc hằng ngày

git init                      # tạo repo mới (một lần)
git status                    # xem file nào đã sửa, đã stage — chạy lệnh này liên tục
git diff                      # xem chi tiết thay đổi chưa stage
git add train.py utils.py     # stage hai file
git diff --staged             # xem chính xác những gì sắp được commit
git commit -m "Thêm checkpoint và resume cho vòng lặp train"
git log --oneline -5          # 5 commit gần nhất, mỗi commit một dòng
Ví dụ từng bước

Bạn sửa train.py, model.py, config.yaml, README.md, rồi chạy:

git add config.yaml
git commit -m "Tăng batch size lên 128"
git status

Commit chỉ chứa 1 file (config.yaml). Ba file kia vẫn ở trạng thái "modified" chưa stage, chờ commit sau. Nếu sau commit bạn lại sửa tiếp train.py, nó cũng hiện là "modified" lần nữa: Git theo dõi thay đổi so với commit gần nhất.

Viết commit message tốt

Một dòng tóm tắt (dưới khoảng 70 ký tự), nói làm gì, nếu cần thì thêm đoạn vì sao:

Kém Tốt
update Sửa rò dữ liệu khi chia train/val theo người dùng
fix bug Chặn NaN khi batch toàn nhãn 0 trong focal loss
final Thêm script đánh giá trên tập test, ghi kết quả ra JSON

Nhìn lịch sử commit, người khác (và bạn 3 tháng sau) phải hiểu dự án tiến triển thế nào.

Quay lui khi lỡ tay

git restore train.py                 # bỏ thay đổi chưa stage, về bản commit gần nhất
git restore --staged train.py        # bỏ stage (thay đổi vẫn còn trong file)
git commit --amend -m "Lời nhắn mới" # sửa commit vừa tạo (chỉ khi chưa push)
git revert a3f9c21                   # tạo commit mới đảo ngược commit cũ (an toàn khi đã push)
git log -p train.py                  # xem lịch sử thay đổi của một file
Lỗi hay gặp

git add . mọi thứ. Lệnh này stage tất cả, kể cả file dữ liệu 2 GB, checkpoint, thư mục .venv, file .env chứa khóa API. Khi đã commit và push, xóa khỏi lịch sử rất mất công. Luôn có .gitignore trước (mục dưới) và chạy git status trước khi commit.

Branch, merge và pull request

Vì sao cần học

Bạn muốn thử augmentation mới nhưng không chắc nó tốt hơn. Branch cho phép thử trên một "dòng thời gian" riêng: hỏng thì bỏ, tốt thì gộp vào. Pull request là cách các đội làm phần mềm (và đội ML) review code trước khi gộp.

git switch -c feature/augmentation   # tạo branch mới và chuyển sang
# ... sửa code, commit vài lần ...
git push -u origin feature/augmentation   # đẩy branch lên GitHub lần đầu
git switch main                      # quay về nhánh chính
git pull                             # lấy thay đổi mới nhất từ GitHub
git merge feature/augmentation       # gộp (hoặc làm qua pull request trên web)
git branch -d feature/augmentation   # xóa branch đã gộp

Pull request (PR)

Trên GitHub, bạn mở pull request để đề nghị gộp branch vào main. Trang PR hiển thị toàn bộ thay đổi, cho phép bình luận từng dòng, và chạy kiểm tra tự động (CI, học ở P8). Một PR tốt có:

  • Tiêu đề rõ như commit message.
  • Mô tả: thay đổi gì, vì sao, đã kiểm tra thế nào (ví dụ "val acc 81.2% → 83.0%, 3 seed").
  • Kích thước vừa phải: dưới vài trăm dòng thì người review đọc kỹ được.

Ngay cả khi làm một mình, dùng PR giúp bạn tự đọc lại thay đổi trước khi gộp và để lại dấu vết dễ hiểu trên GitHub.

Xung đột (conflict)

Khi hai branch cùng sửa một dòng, Git không tự quyết được và đánh dấu trong file:

<<<<<<< HEAD
lr = 3e-4
=======
lr = 1e-3
>>>>>>> feature/augmentation

Bạn sửa file giữ lại dòng đúng, xóa các dấu <<<<<<<, =======, >>>>>>>, rồi git add và git commit. Xung đột là chuyện bình thường, không phải lỗi.

Tự kiểm tra nhanh

Bạn đang ở main có 4 commit. Bạn tạo branch exp, commit thêm 3 lần trên exp, rồi quay về main và merge exp (không có commit mới nào trên main trong lúc đó).

Ví dụ từng bước

Train sống sót qua việc bị ngắt. Lưu checkpoint mỗi epoch vào Drive, và khi khởi động lại thì nạp checkpoint mới nhất nếu có:

import os, torch, torch.nn as nn
torch.manual_seed(0)
X, y = torch.randn(256, 4), torch.randn(256, 1)                 # dữ liệu nhỏ để chạy thử
model = nn.Linear(4, 1); opt = torch.optim.Adam(model.parameters(), lr=0.05)

def train_one_epoch(model, opt):
    loss = ((model(X) - y) ** 2).mean()
    opt.zero_grad(); loss.backward(); opt.step()
    return loss.item()

CKPT = "runs/exp1/last.pt"           # trên Colab: "/content/drive/MyDrive/runs/exp1/last.pt"
os.makedirs(os.path.dirname(CKPT), exist_ok=True)

def train(n_epochs, stop_after=None):
    start_epoch = 0
    if os.path.exists(CKPT):                                      # có checkpoint: nạp và train tiếp
        state = torch.load(CKPT)
        model.load_state_dict(state["model"]); opt.load_state_dict(state["opt"])
        start_epoch = state["epoch"] + 1
        print(f"nạp checkpoint, train tiếp từ epoch {start_epoch}")
    for epoch in range(start_epoch, n_epochs):
        loss = train_one_epoch(model, opt)
        torch.save({"model": model.state_dict(), "opt": opt.state_dict(), "epoch": epoch}, CKPT)
        print(f"epoch {epoch}: loss {loss:.3f}")
        if stop_after is not None and epoch == stop_after:
            print("... phiên Colab bị ngắt ..."); return

train(6, stop_after=2)        # lần 1: bị ngắt sau epoch 2
train(6)                      # lần 2: chạy lại ô, tự train tiếp từ epoch 3

Bài 1

Đếm bằng pipe

tính tay

File train.log có 6 dòng dưới đây. Mỗi lệnh in ra số mấy?

  1. cat train.log | grep ERROR | wc -l
  2. grep -c epoch train.log
  3. grep -v ERROR train.log | wc -l

Nội dung file:

epoch 1 loss 2.10
ERROR cuda out of memory
epoch 2 loss 1.80
WARNING lr too high
ERROR nan loss
epoch 3 loss 1.75
Lời giải

grep ERROR giữ 2 dòng chứa ERROR, wc -l đếm số dòng. grep -c đếm trực tiếp số dòng khớp. grep -v lấy các dòng không khớp: 6 − 2 = 4.

Bài 9

ứng dụng

Dùng: branch, merge, xung đột (conflict) và cách giải quyết.

Bạn thử learning rate mới trên nhánh exp-lr, trong khi đồng nghiệp sửa cùng dòng đó trên main. Tạo tình huống này, merge nhánh vào main, xem file khi bị conflict, giải quyết bằng cách giữ giá trị của nhánh thử nghiệm kèm chú thích, rồi hoàn tất merge.

!mkdir -p conflict-demo && printf "lr: 0.001\nbatch_size: 32\n" > conflict-demo/config.yaml
!git -C conflict-demo init -q -b main && git -C conflict-demo add . && git -C conflict-demo commit -qm "Cấu hình ban đầu"
!git -C conflict-demo switch -q -c exp-lr && sed -i 's/lr: 0.001/lr: 0.003/' conflict-demo/config.yaml && git -C conflict-demo commit -qam "Thử lr 0.003"
!git -C conflict-demo switch -q main && sed -i 's/lr: 0.001/lr: 0.0005/' conflict-demo/config.yaml && git -C conflict-demo commit -qam "Giảm lr còn 0.0005"
